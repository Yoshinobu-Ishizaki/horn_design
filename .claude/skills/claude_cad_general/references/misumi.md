# MISUMI の部品を使う(検査治具・スポット治具で共通)

治具に使う市販部品(ネジ、ノックピン、ブッシュ、ガイドなど)を MISUMI で手配するときの手順。部品を探し、型番を確定し、必要ならモデルを入手し、型番を部品名に残す。

## 1. 部品の調達区分(最初に決める)

| 区分 | 該当する部品 | モデルの作り方 | 型番 |
|---|---|---|---|
| A. 標準品を自作 | ネジ、ナット、ワッシャ、ノックピン、単純な丸棒・スペーサ | build123d で規格寸法から作る。MISUMI のモデルはダウンロードしない | MISUMI の型番を記録する |
| B. カタログ品を入手 | 形状が複雑で build123d で作りにくい部品(ガイド、クランプ、プランジャ、ブッシュ類など) | MISUMI の詳細ページから STEP をダウンロードする | 型番を確定して記録する |
| C. カタログにない形状 | 標準品の寸法変更や加工追加など | Cナビ(図面を描かずに見積もり)または meviy(3D データから AI 見積もり)に登録する | 登録で得た品番を記録する |
| D. MISUMI で手配できない | 曲面がある、材料が特殊などで、C でも作れないもの | build123d で作る | なし(図面で手配) |

- 区分の判断に迷うときは、部品名と理由をユーザーに示して決めてもらう。
- D は図面を作ってローカルベンダーに製作を依頼する。図面化は `step-to-draft`(STEP から DXF)、仕上げは `dxf-drafting-support` を使う。このファイルでは製図の手順を繰り返さない。

## 2. サイト操作(Claude in Chrome 優先、Playwright はフォールバック)

**ブラウザ操作は Claude in Chrome(`mcp__claude-in-chrome__*`)を優先する。** ユーザーのログイン済み Chrome をそのまま使えるので、MISUMI・meviy・Cナビのログインの手間が減る。Chrome が接続できない/使えないときだけ Playwright MCP(`mcp__playwright__*`)を使う。以降の本文は、Playwright の書き方(`browser_*`、`page.getByRole(...)`、`page.mouse.click`)で書かれた箇所が多い。Chrome では次のように読み替える。

### 2-0. Claude in Chrome での読み替え(2026-11-04 に検索まで確認。ほかは未確認)

使う前に `claude-in-chrome` スキルを呼び、`ToolSearch` でツールを一括ロードし(`tabs_context_mcp`、`navigate`、`computer`、`read_page`、`find`、`form_input`、`javascript_tool`、`file_upload`、`get_page_text`)、開始時に `tabs_context_mcp` を呼ぶ。

| 操作 | Playwright | Claude in Chrome |
|---|---|---|
| URL を開く | `browser_navigate` | `navigate` |
| 描画待ち | `browser_wait_for` | `computer`(wait) |
| 画面構造・要素探し | `browser_snapshot`、`getByRole` | `read_page`(interactive)、`find` |
| クリック・キー入力・ホバー | `page.mouse.*`、`page.keyboard.*` | `computer`(left_click、type、key、hover。座標は screenshot の座標系で指定) |
| プルダウン・入力 | `browser_select_option`、`fill` | `form_input`(ref 指定) |
| DOM 調査・リンク収集 | `browser_evaluate` | `javascript_tool` |
| ファイルのアップロード | `browser_file_upload`、`filechooser` | `file_upload`(`<input type=file>` の ref を `find` で取る。メニュー項目を押してネイティブのダイアログを出さない) |
| ダウンロード | `waitForEvent('download')`、`.playwright-mcp/` | ユーザーの既定のダウンロード先に落ちる(下記) |

- 確認済み(未ログインの検索): `https://jp.misumi-ec.com/vona2/result/?Keyword=MSC5-20` を開き、`computer` の wait で数秒待つと、検索結果が出た(型番 MSC5-20 の 1 件)。詳細ページのリンクは、`javascript_tool` で `a` の href を集めて取れる。**戻り値に URL のクエリ文字列を含めると `[BLOCKED: Cookie/query string data]` で遮断される**ので、`href.split('?')[0]` で落としてから返す。
- ビューポートは 1920×911、`devicePixelRatio` は 1。Playwright の「縮尺 0.8 で座標を 1.25 倍」の換算は要らない。ただし screenshot の座標系は 1568×744 で、**クリックには screenshot 上の座標をそのまま使う**(`getBoundingClientRect` の値をそのまま渡すとずれる)。
- **ダウンロードは Chrome の既定の保存先(ダウンロードフォルダ)に落ち、作業ディレクトリには来ない。** 区分 B のモデルは、落ちた zip のパスをユーザーに確かめ、新しい空の `misumi/<型番>/` へ移してから展開する。ダウンロードの許可はユーザーに求める(ファイル名、取得元、大きさを示す)。「CADデータ利用規定」への同意がユーザーの操作である点は変わらない。
- iframe の入れ子の Cナビ、幾何公差のクリック、チェックボックスの絞り込み(`getByRole('checkbox')`)、行名の変更(rename)は、Chrome でどこまで通るか**未確認**。`find`・`read_page` で要素が取れなければ座標クリックにし、通らなければユーザーに操作を頼むか、その部分だけ Playwright に切り替える。通った/通らなかった結果は、この節に日付つきで追記する。
- ダイアログ(alert/confirm)を出す操作は避ける(拡張が応答しなくなる)。

### 守ること

- **ログインはユーザーがする**。IDとパスワードを入力しない。ログインが要る場面になったら止めて、「ブラウザでログインしてください」と頼む(Chrome ではログイン済みのことが多い)。ログイン済みかは、ページの「ログイン・新規登録」のリンクが無いことで確かめる。
- 区分 B のダウンロード、Cナビ、meviy はログインが要る。検索と型番の確定は未ログインでできる。
- **カートへの追加、見積、注文はしない**。型番の確認とモデルの入手までで止める。見積と注文はユーザーが行う。
- **meviy へのアップロードは、そのつど確認する**。治具や製品のモデルが社外のサービスに送られるため。何を送るかを示してから、ユーザーの了解を得る。
- 画面の描画が遅い。ページを開いた直後は中身が空なので、`browser_wait_for` で数秒待ってから読む。

### 2-1. 探す(確認済み・未ログイン)

1. キーワード検索の URL を直接開く: `https://jp.misumi-ec.com/vona2/result/?Keyword=<キーワードまたは型番>`(日本語は URL エンコード)。
2. 左の絞り込み(カテゴリ、材質、呼び径、長さなど)で候補を減らす。結果の件数と型番の候補数が出る。
3. 候補の詳細ページは `https://jp.misumi-ec.com/vona2/detail/<シリーズコード>/`。検索結果の `a` 要素の href から取れる(`browser_evaluate` で `/vona2/detail/` を含むリンクを集める)。

### 2-2. 型番を確定する(確認済み・未ログイン)

- 型番が分かっているなら、`Keyword=<型番>`(例: `MSC5-20`)で検索する。1件に絞られ、詳細ページの URL に `HissuCode=<型番>` が付く。この URL が「型番を確定した状態」。
- 型番が分からないなら、詳細ページで寸法の項目(呼び径、長さ、材質など)をすべて選ぶ。「未確定:候補が N 型番あります」の表示が「確定しました」に変わり、型番が出たら確定。
- 絞り込みは、左のパネルのチェックボックスを `page.getByRole('checkbox', {name: '<値>', exact: true})` で押す(`browser_run_code_unsafe`)。1つ押すごとに 2.5〜3 秒待つ。同じ値が複数の項目にあるとき(例: `4` はねじの呼びと長さの両方にある)は、パネルの上から順(ねじの呼びが先、長さが後)に `.first()` で選び、押したあとの選択状態を読み返して確かめる。
- **選択肢は系列ごとに違う**。例: 低頭六角穴付ボルトのステンレスで、MISUMI の「低頭六角穴付ボルト【メカニカル部品カタログ掲載】」(SUSXM7)は M4 で長さ 5〜25 しかなく、35 は無い。ほかの系列(SUNCO の「低頭六角穴付ボルト ステンレス 表面処理なし」など)には M4 の 35 がある。長さが無いときは、別の系列の詳細ページで同じ絞り込みを試す。
- 事例: M4・ステンレス(SUS304相当)・低頭・長さ 35 は、「低頭六角穴付ボルト ステンレス 表面処理なし」(SUNCO、`/vona2/detail/221303783852/`)で型番 `CSHBTT-SUS-M4-35` に確定(半ねじ、ピッチ 0.7、バラ 1 個から、単価 462 円・在庫品 1 日目。2026-10-25 時点)。
- 依頼の言葉が「M6」のようにねじにも公差にも読めるときは、解釈を言ってユーザーに確かめる(ノックピン φ6 の「M6嵌合」は、ねじ M6 ではなく、はめあい公差 m6 だった)。ピンの検索は「ノックピン 内ねじ」で、タップ付き(`m6`、`h7`、精級、p6 など)の系列が出る。
- 長さなど、依頼で決まっていない項目は選ばずに、選択肢を示してユーザーに決めてもらう(型番リストは、詳細ページの「型番リスト」に確定前でも候補が並ぶ)。
- ノックピンの長さは、孔の深さから選ぶ。孔深さ以下で、標準にある最も長い長さを選ぶ(ピンが孔の底に当たらず、頭が孔の口から出ない)。選んだあとの余り(孔深さ - ピン長さ)をユーザーに伝える。系列の最長が孔深さに届かないなら、余りが大きすぎないか確かめ、必要なら別の系列を探す。
  - 事例: φ6、はめあい公差 m6、タップ付き、孔深さ 53 → `MSTM6-50`(MISUMI 自社品 `/vona2/detail/110100141050/`、SUJ2、ねじ M4×0.7、ねじ深さ 8、エアベントあり、単価 545 円・在庫品 1 日目。2026-10-25 時点)。長さは 50 が最長で、頭は孔の口から 3 mm 奥になる。同じ φ6・m6 でも、「内ねじ付平行ピン m6」(`221006225516`)には長さ 55・60 があるが、53 を超えて口から出る。
  - ねじの呼びは、規格表の行の並びから読んだ(φ6 は M4×0.7、φ5 は M3×0.5)。表が崩れて読めるので、確定後に型番ページの規格表で確かめる。
- ダイセット用プレーンガイドポストセットの型番は、ポスト取付方法とブシュで文字が変わる。圧入ポストは `PD`/`PZ`/`PF`/`PFZ`(例: `PD2014L5` = ポスト φ20、長さ 140、`L` はロックタイト接着、ブシュ長さ 50)。着脱ポストは `RD`/`RZ`/`RF`/`RFZ`(例: `RZ20125` = ポスト φ20、長さ 120、ブシュ長さ 50。RZ は無給油で接着はロックタイトのみのため、`L`/`M` の文字が入らない)。ポスト取付方法を変えたら、長さの範囲も変わる(着脱ポスト MRP の φ20・φ22 は長さ 80〜120 まで)。
- 着脱ポストは、座面(フランジの下面)から先端までが L。座金とボルトが下面に付くので、板の下面の座ぐりが要る。座金を板に埋めるための最小の板厚が、板厚の規格(フタバの NS 100×80 は 35 mm)を超えることがある(φ20 は 39 mm、φ22 は 40 mm)。
- 範囲指定の項目(例: ブロック高さ L が「20-80/0.1mm単位」)は、左のパネルのテキスト入力欄に値を打つ。欄をクリックし、`Control+A` のあと 1 文字 150 ms 間隔で打ち、`Tab` で確定する。1 つ入れると、ほかの項目の範囲が狭まる(例: L1 を入れると L の上限が変わる)。
- 追加工(例: LKC = L 寸法の公差を ±0.01 に変更)は、型番の確定後に、ページ上の「追加工・オプションを見る」を開き、チェックボックスで選ぶ。選ぶと型番の末尾に記号が付く(`SBV20-42.5-Y-40` → `SBV20-42.5-Y-40-LKC`)。カタログの注文例にも、末尾に追加工の記号を付ける書き方が載っている。
- 項目が選択済みのとき、別の値を押すと、ほかの選択が外れることがある(例: ストロークエンドブロックなどで、確定後に別の追加工の値を押すと、系列の選択が崩れた)。値を変えるときは、ページを開き直して、上から順に選び直す。選んだあとは、型番の表示と仕様表で、全項目を読み返す。
- 範囲の選択肢が数字のボタンで並ぶ項目(例: シャンクの MLC)は、同じ数字が別の項目(外径など)にも出ることがある。`getByRole('checkbox', {name: '<数字>'})` が複数に当たるので、画面を撮影して、ボタンの位置で押すと確実(画面のスクロールで位置がずれるので、押す直前に撮り直す)。
- ダイセット用シャンク(MSK、MSKS、MSKTP): D(ポスト径)ごとに、ねじ M とボディ長さ L が規格で決まる(D=25 は L=50、32 は 55、38 は 60、50 は 65)。MLC(ML 寸法変更)で変えられるのは、植込みの長さ ML だけ。突出長さ(L)は変えられない。
- 価格は、型番を確定してから、ページの「価格を確認」ボタン(見るだけで、カートや注文ではない)を押すと、単価・合計・出荷日が出る。数量による割引の段(例: 1〜9、10〜19、20〜30、31〜49、50〜)も表で出る。在庫品はボタンを押さなくても、型番の表示行に単価が出ることがある。
- Cナビの価格は、チェック OK のあと「価格表示」→「数量ごとの価格・納期を確認」を押すと、「価格計算書」の PDF が窓で開き、数量の段ごとの単価と納期が読める(画面を撮影して読む)。1 注文が 3,000 円未満だと、別途送料 450 円(注記)。
- 確定した型番は、必ずページに表示された文字列をそのまま記録する。型番の規則を推測して組み立てない。
- 価格は、型番を確定して「価格を確認」を押したあとの表示が最新。カタログの価格表は古い(詳細ページにも「23年4月時点」とある)。価格は設計の判断に使わず、必要なら参考として書く。

### 2-3. モデルを入手する(区分 B。ログインが要る。画面は初回に確認する)

詳細ページに「3Dプレビュー」「CADデータダウンロード」「My部品表保存」のボタンがある(確認済み。型番確定後、ページ中ほどの「型番: <型番>」の行に並ぶ)。

- 「CADデータダウンロード」を押すと、まず「CADデータ利用規定」のダイアログが出て、「同意する」「同意しない」を選ぶ(確認済み)。**同意はユーザーがする**。Claude は押さず、ダイアログが出ていることを伝えて待つ。
- 同意すると「2D/3D CADデータ」の欄が出る(確認済み)。「ファイル形式」のプルダウンから `STEP(AP214)` を選び(ほかに `STEP(AP203)`、DXF、DWG、IGES、Parasolid など)、「データ生成」を押すと `<型番>_STEP.zip` のダウンロードが始まる。zip の中身は `<型番>.stp`。
- 同意はブラウザのセッションが続く間は覚えられるかもしれないが、未確認。ダイアログが出たら毎回ユーザーに頼む。
- Playwright のダウンロードは、作業ディレクトリの `.playwright-mcp/` に落ちる(zip 名のハイフンは `MSC5-20-STEP.zip` のように変わることがある)。`.gitignore` に入れてある。ここから新しい空の `misumi/<型番>/` へ移して展開する。
- 事例(MSC5-20): 1 ソリッド、体積 381.8 mm3、外形 20 × 5 × 5(φ5 × 長さ 20)、単位 mm、軸が X 方向で原点は端面の中心。取り込んだら軸の向きと原点を確かめてから配置する。
- 規約の同意は、新しく開いたページごとに求められることがある(同じセッションで、続けて 2 つ目を取るときは出ないこともあった)。出たら、そのつどユーザーに頼む。
- 形式の `select` は、ページに複数ある(表示件数の `select` など)。「STEP」を選択肢に持つものを探す。2/3D CAD の画面の形式は、型番の系列によって `STEP`、`STEP(AP214)` などと表記が違う。
- ダウンロードは、`browser_run_code_unsafe` で `page.waitForEvent('download')` を待って、`download.saveAs(...)` で保存できる。zip の中身は `<型番>.step`(または `.stp`)。複数部品のセットは、1 つの STEP に複数ソリッドで入る(着脱ポストのセットは、ポスト、座金、ボルト、ブシュの 4 つ)。
- セットの STEP は、部品ごとの原点が違う(ブシュはポスト先端側に別の高さで入っている)。取り込んだら、ソリッドごとに外形と円筒面の径・範囲を出して、形を確かめる(例: `inspect_set.py` 相当の確認)。
- 型番を確定してから「CADデータダウンロード」を開く。
- ログイン後は、ヘッダに「注文履歴」「My部品表」が出る。「My部品表保存」は型番を My部品表に保存する機能で、品番の登録に使えそう(挙動は未確認。使う前にユーザーと確認する)。
- 保存先は部品ごとに新しい空のフォルダにする: `jigs/<治具名>/.../misumi/<型番>/`。ファイル名に型番を含める。
- ダウンロードしたファイルは信用しないデータとして扱う。build123d の `import_step` で読むだけにし、そのフォルダの中でスクリプトを実行しない。
- 読み込んだら、体積と外形(バウンディングボックス)をカタログの寸法と照合してから使う。単位(mm)も確かめる。

### 2-4. meviy(区分 C。ログインが要る。画面の入口まで確認済み)

Cナビとは別のサイトで独立している。まず meviy から整える。Cナビは 2-5。

確認済み:
- 入口は `https://meviy.misumi-ec.com/ja-jp/login/`。MISUMI と同じ会員 ID を使い、MISUMI にログイン済みなら開くだけでマイページ(`/ja-jp/app/fa/mypage`、「マイプロジェクト一覧」)に入れる。入れないときはユーザーにログインを頼む。
- 一覧の列は「プロジェクト名」「購入履歴」「型番」「加工方法」「材質」「表面処理」など。3D CAD(`.step`、`.stp`、`.x_t` ほか)をドロップするか、「アップロード」→「ファイルをアップロード」「フォルダをアップロード」で登録する。
- 加工は切削(角物・丸物)、板金、板金溶接、樹脂などから選ぶ。見積の結果は「自動見積」「担当者見積」「見積不可」のタブに分かれる。
- 図面(PDF・DXF・DWG)の場合は別の meviy2D(`/ja-jp/2dx/meviy2d/`)でアップロードする。区分 D のうち、MISUMI の「2D図面加工品」で作れるものはこちらも選べる。

アップロードから条件設定まで(電極台の板 ELECTRODE-PLATE で試行して確認済み):
1. 部品だけの STEP を `output/` に出力する(`make_plate()` の板。X70 × Y31.5 × 厚さ10、体積 20611.0 mm3)。
2. 一覧で「アップロード」→「ファイルをアップロード」。Playwright では、このメニュー項目を押したあとに `browser_file_upload` でパスを渡す。完了すると一覧に行ができ、「自動見積」のタブに数が出る。

- 一覧の行の名前の変更(確認済み): 行の名前のセルの鉛筆の印(`div[class*=renameIcon]`)を押すと、その行の名前が入力欄になる(1 行ずつ。別の行の鉛筆を押すと、前の入力欄は閉じる)。Playwright では、行を部品の ID(行の名前のリンクの href の `partsview/<部品ID>`)で特定し、`xpath=//a[contains(@href,'<部品ID>')]/ancestor::div[contains(@class,'renameContainer')][1]` を `hover()` → その中の renameIcon を `click({force: true})` → 開いた `input[type=text]`(値が `*.stp`)を `fill` → `Enter`。名前の文字そのものを押すと部品のページへ移動するので、座標でのクリックは避ける。同じ名前の行(再送したもの)は、古い行に「旧_削除可_」を付けて見分ける。

### 2-5. Cナビ(区分 C。入口と流れまで確認済み。寸法入力以降は未確認)

meviy とは別のサイトで、独立している。meviy は 3D モデルを送るのに対し、Cナビは**寸法を画面に入力して加工部品を指定する**(モデルを社外に送らない)。決まった形(プレート、ブラケット、ブロック、ピン、ブッシュなど)の寸法違いに向く。

確認済み:

寸法入力画面の操作(電極台の板 70 × 31.5 × 厚さ10 で試行して確認済み。金属プレート `JUDZT`):
1. 画面は iframe の入れ子で、材質や寸法の入力欄は描画された部品。DOM のセレクタでは操作できないので、**座標を指定したクリックとキー入力**(`browser_run_code_unsafe` の `page.mouse.click`、`page.keyboard.type`)で操作する。座標は画面のスクリーンショットで読む(ウィンドウサイズが同じなら再現する)。
2. Step1: 材質のドロップダウンを開き、行を選ぶ(事例は `SS` = SS400・処理無、実働出荷日 3 日、ストック×)。材質コードのほかに、四三酸化鉄皮膜(`SSB`)、無電解ニッケル(`SSM`)、ユニクロ(`SSU`)、S50C、A5052 などがある。
3. Step2: パラメータ指定の欄に A、B、T を入力する(JUDZT は A 25〜500、B 10〜300、T 3〜50、いずれも 0.1 mm 単位。4 角は C2 以下)。**入力は欄をクリックして 0.8 秒待ち、`Control+A` のあと 1 文字 200 ms 間隔で打ち、`Tab` で確定する**。速く打つと先頭の文字が落ちる(試行で `31.5` が `1.5`、`10` が `0` になった)。入力後は画面の寸法表示と「現在の設計型番」(例: `JUDZT-SS-A70-B31.5-T10`)で値を確かめる。
4. 「チェック実行」を押すと、Step3 に「規格チェック結果:OK」(範囲外なら NG と内容)と重量(事例は 174 g)が出る。値を直したら、**もう一度チェック実行を押す**(前回の NG が残る)。
5. チェック OK になると、下に「価格表示」「PDF出力」「DXF出力」「Myページに保存」「カートに追加」と、任意の「穴や切り欠きを追加する」(追加工プラスワン)が出る。
6. 「穴や切り欠きを追加する」→ 加工面の選択(A〜F の面の記号をクリック)→ 面編集の画面(座標軸の基点、追加工のリスト、位置 X・Y と回転、補助線、図面に表記する名称・図番、干渉チェック、編集完了)。「追加工の選択」は別タブで開き、種類は 穴(キリ穴、皿穴、長穴、タップ穴 並目・細目(通し)、ザグリ穴、精度穴(通し)、精度穴2個(通し))と 切欠(角切欠、R切欠、テーパー)。配置済みの追加工の寸法は変えられず、変えるときは削除して作り直す。
7. 面編集のあとに「部品保存」の画面(「型番を発行してカートに追加」「Myページに保存」「価格・納期確認」「設計図確認(PDF)」)に進む。「発注型番はカート追加(保存)後に発行されます」と表示される(確認済み)。型番の形式は、保存したあとでないと分からない。

守ること:

## 3. 型番を部品名に反映する

- 部品名は `<役割>_<型番>` とする。例: `PIN_MSC5-20`(区分 A・B・C)。役割は英大文字の短い語(`PIN`、`SCREW`、`BUSH`、`GUIDE` など)。
- 同じ型番の部品が複数あるときは、アセンブリ STEP で名前が 1 つに集約されないよう、末尾に連番を付ける(`PIN_MSC5-20_1`、`PIN_MSC5-20_2`)。`unique_names` で部品ごとに形を複製するのは従来どおり。
- 区分 D(型番がない)の部品名は、ユーザーに決めてもらう。図番を付けるか、役割名だけにするかを聞く。決まるまでは役割名だけにする。
- 型番が未確定の部品は、`<役割>_TBD` とし、設計手順書の未確定の事項に書く。

## 4. 部品表(BOM)

設計手順書に、使う市販部品と製作部品の一覧を載せる。

| 部品名 | 区分 | 型番 | 数量 | モデルの出典 |
|---|---|---|---|---|
| PIN_MSC5-20 | A | MSC5-20 | 2 | build123d(規格寸法から) |
| PLATE_MVBLK-SSN-4PL-979DW | C(meviy) | MVBLK-SSN-4PL-979DW | 1 | build123d の `make_plate()` を STEP にして meviy へ(`output/meviy_test/`) |
| (例)GUIDE_xxx | B | (確定した型番) | 1 | `misumi/<型番>/` の STEP |
| (例)HOLD-PLATE | D | なし | 1 | build123d。図面でローカルベンダーへ |

- 出典は、build123d で作ったか、ダウンロードした STEP のパスか、を書く。
- 区分 B のダウンロードをしたときは、日時と型番を `worklog.md` にも残す。
