# 設計手順書のテンプレート

最後に作業フォルダへ `design_procedure.md` として作る。**試行錯誤を除き**、同じ STEP から同じ治具を再現できるように、最終の形・寸法・コマンドだけを書く。経緯は `worklog.md` にある。
書式の決まり: 英数字と記号は半角、日本語は全角(NFKC)。画像は `![](パス)` で、`[]` の中(alt)は空にする。
実例は `example_bb106_design_procedure.md`(画像リンクは元の作業フォルダの相対パスなので、この例では外してある)。

## 章立て

```
# 検査治具の設計手順 (<案件名>)
<1段落: 何のための手順書か。経緯は worklog.md>
![](<組立の ISO 図 PNG>)

## 1. 対象と構成
- 入力: <STEP のファイル名と製品の形>
- 受ける面・受けない面
- 部品の表: 部品名 | 内容 (BASE、受け、ボルトなど)。製法(3Dプリント / 組立)

## 2. 環境
- uv、build123d、OCP CAD Viewer。作業場所。面・エッジの番号の定義(import_step の faces()/edges() の順)

## 3. 手順
### 手順 1: 面・エッジに名称を付ける       (名称表、render_names のコマンド、画像)
### 手順 2: 軸などの基準を求める           (円筒の軸、半径、範囲)
### 手順 3: 置き方向と座標系を決める       (回転角、原点の決め方、orient_step のコマンド、回転後の値の表、画像)
### 手順 4: 基準の点を求める               (名前つきの点と座標)
### 手順 5 以降: 部品ごとの作り方          (寸法、式、面取り。順番どおりに)
### 締結(組立のとき)                      (ボルト品番、位置の表、穴の寸法、かかり)
### 文字・注記(あるとき)                  (内容、フォント、位置、組立品での扱い)

## 4. 検証
期待値の表: 体積、部品どうしの重なり、当たり面の被覆、アンダーカット、ソリッドの数。

## 5. 出力
コマンドと出力先(STEP / STL / PNG)。出力先のフォルダが git 管理外かどうか。手順書に載せる PNG の置き場所。

## 6. 未確定の事項
(あれば。ボルトの肉厚が薄い、はめあいは公差で指示する、古い出力ファイルなど)

## 7. 備考: 設計にかかった時間とやり取り
表: 作業時間(内訳)、指示の件数、確認の質問の回数、コミットの数、作り直し。
補足3点: 短い指示で1往復で済んだこと、時間のかかった所、この手順書どおりなら短くできる見込み。
```

## 書くときの注意

- 値は、モデルのコードの最終の定数と、検証で測った値をそのまま写す(推測で書かない)。
- 式がある寸法(例: 傾いた円柱の下端、円錐の半径)は、式と結果の数値の両方を書く。
- 「仮定」のものは未確定の事項に残す。ユーザーが確定したら外す。
- 時間は `worklog.md` の epoch から、指示とコミットの数は指示ログと `git log` から数える。
- 手順書に載せる PNG は、git 管理外の出力フォルダの外に置いてコミットする。
